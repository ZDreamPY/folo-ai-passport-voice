# 随身 AI 语音故障排查

检查顺序：**设备联网 → 电脑托盘/转发器 → VB-CABLE → 默认麦克风 → 输入法快捷键 → 实际声音 → 出字**。

托盘运行后，设置面板在 **http://127.0.0.1:38765**，可随时查看当前热键、触发方式和音频输出。
先确认 **Windows 设置 → 系统 → 声音 → 输入** 已选择 **CABLE Output (VB-Audio Virtual Cable)**。
安装驱动不会自动代替这个选择。完整点击步骤见 [虚拟声卡配置](QUICKSTART.zh-CN.md#virtual-cable)。

| 现象 | 判断与处理 |
| --- | --- |
| 未安装 VB-CABLE / 找不到 CABLE Output | 双击 **windows/install.cmd**：自动从 [VB-CABLE 官网](https://vb-audio.com/Cable/) 下载驱动包并以管理员启动安装器，装完**必须重启电脑**；重启后在语音输入法里把识别麦克风选为 **CABLE Output**。自动安装失败时到官网手动下载驱动 ZIP，解压后右键 `VBCABLE_Setup_x64.exe` 以管理员身份运行 |
| 等待电脑 / 与电脑断开 | 托盘是否在运行（双击 start.cmd 启动）；设备和电脑是否同一可互通局域网；检查访客隔离、可信专用网络的程序防火墙权限及 VPN 局域网路由 |
| 设置面板打不开 | 确认托盘已启动；双击托盘图标即可打开面板；地址用 http://127.0.0.1:38765。提示端口被占用时，托盘会自动打开已运行实例的面板，不要重复开托盘 |
| 电脑已连接，麦克风通道未就绪 | 心跳已通，但音频或快捷键未就绪。看面板“语音通道”提示与日志，检查音频输出是否为 CABLE Input；只运行一个托盘/转发器 |
| WinError 10048 / UDP 33333 绑定失败 | 端口已占用，先确认是否重复启动了自己的托盘；按下文查进程，不随意改端口 |
| 没找到 CABLE Input | 运行 install.cmd 安装 VB-CABLE、重启电脑，用 --list-devices 检查；面板的音频输出设备应选 CABLE Input |
| 打开声卡失败 | 核对播放端启用状态、占用声卡的独占模式软件和具体错误；不同后端都失败时不能用设备麦克风 |
| 显示就绪，上键却打不开语音 | 在记事本点出光标、切到目标输入法；先用实体键盘试同一快捷键，核对左右 Shift 与 hold/tap |
| 松开上键仍录音 / 再次打开语音 | 先核对面板触发方式 hold/tap 是否匹配，再确认用的是本版 EXE 和固件。旧版或丢失结束报文可能保留状态；本版加入超时释放、下键状态对账。不要只凭此现象认定一定是输入法设置错误 |
| 输入法打开，没有文字 | 先确认 Windows / 输入法音源是 CABLE Output，再录一段设备声音；有声时查输入法语言、联网和识别服务，无声时查传音路径 |
| 识别整句话都不准 | 回放 CABLE Output 录音。失真/断续/太小时检查设备收音与网络，清楚时检查输入法音源、语言与识别；不要盲目增加增益 |
| 只漏开头 | 等电脑语音界面出现，再开始说话 |
| 电脑麦克风有声，设备没有 | 很可能选错音源；系统和输入法选 CABLE Output，按住设备上键，再看该录制端电平 |
| 改键位没生效 | 面板点“保存设置”后即时热生效；确认保存成功、面板显示的已是新值。手动改过 voice-config.json 的核对文件名、UTF-8 与 JSON 语法；仍无效时点面板“重启转发器”或重启托盘 |
| 按下键电脑切窗口 / 确定键不回车 | 0.3.0 默认：下键=切窗（Alt+Tab，迟滞默认 1000 ms，可在面板 100–3000 调整），确定键（OK 键）=Enter。在面板“按键动作”里核对自己录制的键位 |
| 退出后快捷键似乎没释放 | 松开设备键，按下再松开对应实体键；退出托盘后重新启动。程序强杀或电脑异常退出无法保证正常清理 |
| 按确定键不换行/不发送 | 先松开上键、等识别完成，确认目标输入框有焦点；面板“按键动作”确认 OK 键录的是 Enter。记事本先测试换行，聊天软件需设置为“回车发送” |
| 插 USB 却找不到设备麦克风 | USB 用于供电/烧录；语音走 Wi-Fi + 托盘转发器 + VB-CABLE，不是 USB 声卡 |
| 托盘没出现或直接退出 | windows 目录终端运行 cmd /k start.cmd 保留错误，再诊断；不要在 ZIP 预览里启动 |
| 烧录提示分区不一致 | 保留备份，核对硬件并按固件附录处理，不跳过校验强刷 |

## 1. 快捷键配置检查

输入法和电脑端两边都要改，只改一边不够。
看 [设置面板配置](QUICKSTART.zh-CN.md#mapping)，确认：

- 打开设置面板 http://127.0.0.1:38765，核对**热键**与**触发方式**（hold/tap）和输入法一致。
- **音频输出设备**是 **CABLE Input**。
- 面板点过**保存设置**，显示的已是新值；仍无效时点“重启转发器”。

手动改过 **windows/voice-config.json** 的再检查：文件在 EXE 旁、不是 example 或 .json.txt，JSON 语法有效。
JSON 读取失败可能退回默认配置。PowerShell 在 windows 目录校验：

```powershell
Get-Content -LiteralPath .\voice-config.json -Raw -Encoding UTF8 | ConvertFrom-Json -ErrorAction Stop
```

命令行参数优先于 JSON；如果使用自建快捷方式带 --key / --mode 参数，检查快捷方式目标。
确定键默认发送 Enter、下键默认切窗（Alt+Tab），两者都可在面板“按键动作”里重新录制。

## 2. 查找端口占用

PowerShell 查询：

```powershell
Get-NetUDPEndpoint -LocalPort 33333 | Select-Object LocalAddress,OwningProcess
```

记下结果里的进程号，在任务管理器“详细信息”核对，或执行 `Get-Process -Id` 后加实际进程号。
只结束确认是自己转发器的进程；不要照抄别人 PID，也不要批量结束所有 Python 进程。
diagnose.cmd 检查时若自己的转发器仍运行，BUSY 是正常现象；先退出托盘再诊断。

## 3. 广播发现失败

同一可信局域网允许单播、但广播发现受阻时，在设置面板“设备连接”里填设备实际局域网 IP 并保存，
从路由器客户端列表核对地址。面板保存后转发器会自动重建连接；它不能绕过 AP 客户端隔离，
也不能让不在同一网络的设备凭空互通。设备地址变化后需同步修改或清空。

## 4. 网络、就绪和真实出字分开验证

“电脑已连接”是收到心跳，麦克风与快捷键就绪才允许传音。
电脑端就绪还不能证明系统/输入法选对音源。用语音应用包中的电脑程序，按 [记事本验收](QUICKSTART.zh-CN.md#first-test) 测试，
再按 [电平与录音检查](QUICKSTART.zh-CN.md#daily) 确认设备声音。

诊断工具只检查语法、声卡端点/格式与 UDP 33333，不能代替真实说话测试，也不能确认输入法设置。
让 Codex 排错时可复制 [辅助配置说明](CODEX_SETUP.zh-CN.md) 中的流程，给它脱敏后的错误与实际设置。
